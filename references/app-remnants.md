# Uninstalled apps, login items, and extensions

1. Establish the product and exact bundle identifiers. Check installed app locations, nested app components, package receipts, and executable destinations. Check whether an apparently absent app shares a helper with an installed product.
2. Compare System Settings → General → Login Items & Extensions with user and machine LaunchAgents, machine LaunchDaemons, helper executables, and registered extensions. Inspect plist `Label`, `Program`, and `ProgramArguments`, and check the exact launchd domain. An `open`, shell, or interpreter wrapper can exist while its actual destination is gone. Treat `sfltool dumpbtm` as optional diagnostic evidence subject to macOS permissions.
3. Separate background registrations, caches, settings, containers, sync files, and installer receipts. Generic or similarly named directories can contain compatibility manifests placed by other software. A package receipt is installation bookkeeping and does not prove that the app or service is present. Group Containers and File Provider data may have other owners or pending data.
4. Prefer the vendor uninstaller or native controls when applicable. For an identified stale launch job, stop just that job if loaded and within scope, move its own plist to a recovery location, then refresh and reopen Settings as necessary. Check the list directly when accessible. Avoid using a global background registration reset to remove one item.
5. For ancillary app data, verify the exact identity and authorize data-bearing candidates through the user's scope. Keep cloud copies and synced working folders separate. If macOS blocks a protected container or root-owned receipt, use approved native authentication and record anything still blocked. Verify both path absence and absence of the registration when they were cleanup targets.

Primary reference: [Apple deployment guide for login items and background tasks](https://support.apple.com/guide/deployment/manage-login-items-and-background-tasks-depdca572563/web).
